# Contributing

This project is developed in public but is not an open-license publication. Issues that identify errors, stale references, unclear explanations, and missing architecture trade-offs are welcome.

## Chapter contract

Before proposing a chapter, read the [chapter template](docs/appendix/chapter-template.md). A chapter should teach a decision, not merely describe a technology. It must include measurable outcomes, at least one trade-off, a diagram or decision table where useful, a practical artifact, self-check questions, and dated sources.

## Pull requests

- Keep one conceptual change per pull request.
- Preserve vendor-neutral language in the main explanation; place vendor mappings in clearly marked sections.
- Do not add unverified benchmark claims or unsourced regulatory guidance.
- Update the chapter's `Last reviewed` date when materially revalidating it.
